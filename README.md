# OniichanCamera

映画撮影監督・写真家・カラーサイエンティストの視点で設計した、iOS 向けプロフェッショナル・シネマティックカメラアプリです。
「撮影プレビューと保存写真の色が同じであること」を最重要の設計原則としています。

---

## 1. 開発環境とビルド

| 項目 | 内容 |
| --- | --- |
| 対応端末 | iPhone 16（iPhone / iOS 17.0 以降） |
| 言語 | Swift 5 |
| フレームワーク | SwiftUI / AVFoundation / PhotoKit / Core Image / Metal / Core Motion |
| プロジェクト | `OniichanCamera.xcodeproj`（Xcode 16 以降の同期フォルダ形式） |
| 外部ライブラリ | なし（Apple 純正フレームワークのみ） |

### ビルド手順

1. macOS（Xcode 16 以降）で `OniichanCamera.xcodeproj` を開く
2. ターゲット `OniichanCamera` → `Signing & Capabilities` で自分の開発チームを選択
3. **実機（iPhone）を選択して Run**（カメラ・センサー系は実機必須）
4. 初回起動時にカメラ / 写真ライブラリの許可を求める

> シミュレータではカメラ映像が取得できないため、プレビューは黒く表示されます。
> ヒストグラム・ルック・設定・写真管理の UI はそのまま確認できます。

## 2. 設計思想

### A. 写真の品質 — 画質は「調整値」ではなく「パイプライン」で決める

すべての画質処理は `Image/ColorPipeline.swift` に実装された単一の処理経路を通ります。

```
色温度/ティント → 露出(EV) → トーンカーブ → ルック 3D LUT → 彩度/彩度保持/色相 LUT
→ カスタム LUT → 明瞭度/シャープネス → 粒子感 → 周辺光量
```

- **トーンカーブ**：ハイライト / シャドウ / コントラスト / フェードから 5 点のカーブを動的構築
  （白飛び・黒つぶれを抑えつつ、階調を破綻させない）
- **3D LUT**：ルックと色調整は 32³ / 16³ のカラーキューブとして構築し、
  `CIColorCubeWithColorSpace` で適用（sRGB カラースペース指定）
- **粒子感**：単色ノイズのソフトライト合成。フィルム粒子を意識した低コントラストの粒
- **周辺光量 / 明瞭度**：撮影解像度に応じて半径をスケーラブルに調整

### B. WYSIWYG（プレビューと保存写真の一貫性）

- プレビュー：`AVCaptureVideoDataOutput` のフレーム → `ColorPipeline` → Metal で描画
- 保存：`AVCapturePhoto` の画像データ → **同じ `ColorPipeline`** → HEIF / JPEG にエンコード
- 無調整（ルック強度 0・調整なし・LUT なし）の場合は**元の圧縮データをそのまま保存**し、
  再エンコードによる画質劣化を完全に回避
- 高解像度撮影（48MP 級）は GPU メモリを圧迫しないよう 32MP 相当へ縮小してから処理
  （通常の 24MP 撮影はフル解像度で処理）

### C. 映画的な色彩表現

ルックは「フィルター」ではなく、階調・色相・彩度・スプリットトーニング・粒子・
周辺光量まで含めて設計したレシピ（`Models/LookRecipe.swift`）です。

| ルック | 設計意図 |
| --- | --- |
| Natural | 忠実な階調。肌の再現性を最優先した基準 |
| Cinematic | 影に寒色 / 光に暖色。抑制的な彩度とフィルム粒子 |
| Muted | 彩度を繊細に抑えた静かなトーン |
| Contrast | 黒は締め、白は破綻させない明暗表現 |
| Noir | モノクローム寄りの退廃的な暗部と強い周辺減光 |
| Warm | 肌がきれいに見える夕方の光 |
| Cool | 北欧の朝のような青みの効いた色調 |

- 各ルックは **0〜100% の強度調整**が可能（入力色と変換色の線形補間で実現）
- 自然な彩度は「彩度の低い色を優先して持ち上げ、肌色（橙〜赤）の変化を半減」する実装
- カスタム LUT（Impulse `.cube`）の読み込みに対応（設定 → 画像調整）

### D. 初心者でもすぐ使える

- 起動直後は AUTO モード。露出・フォーカス・ホワイトバランスはすべて自動
- ルックは Natural が初期値。タップ 1 回で別ルックに切替可能
- 撮影補助（グリッド・水平器・ヒストグラム等）は必要なものだけチップからオン

### E. 撮影体験

- プレビューを画面いっぱいに確保し、操作は上端・下端に集約
- ダークベースの iOS ネイティブなデザイン。不要な装飾なし
- 触覚フィードバック、撮影フラッシュ、カウントダウン表示
- 画面スリープ防止、バックグラウンド移行時のセッション安全停止

## 3. 実装機能

### 撮影モード

- **AUTO**：自動露出 / 自動フォーカス / 自動 WB / 露出補正 / タップで AE・AF
- **PRO**：ISO / シャッタースピード / フォーカス位置 / WB（ケルビン・ティント）/ AE・AF ロック
  - すべて数値表示付きスライダー。実機の `activeFormat` から取得した **実際の調整可能範囲** だけを提示
  - 実測値（実際の ISO / シャッタースピード / レンズ位置）を常時表示

### 撮影補助（すべて個別オン・オフ、不透明度と色を変更可能）

グリッド（三分割 / 黄金比 / センター）・水平器（Core Motion）・ヒストグラム（RGB + 階調、
白飛び・黒つぶれ警告付き）・ゼブラ表示・フォーカスピーキング・セーフティガイド・
アスペクト比ガイド（4:3 / 16:9 / 1:1 / 2.39:1）・タップフォーカス表示

### シャッター

通常撮影 / 3・5・10 秒タイマー / カスタムタイマー（1〜60 秒）/ 連写撮影（2〜10 枚）/
撮影時の画面フィードバック / フラッシュ（オン・オフ・オート）

### 保存フォーマット（実機能力を実行時判定して表示）

| 形式 | 内容 |
| --- | --- |
| HEIF | 既定。ルック適用済み・品質 93% |
| JPEG | 互換性優先・品質 95% |
| RAW (DNG) | センサーの生データを無改変で保存 |
| Apple ProRAW | 対応機種のみ表示 |

- RAW / ProRAW では **DNG は一切変更しません**。ルックと画像調整は同時に保存される
  現像済みコピー（HEIF）にのみ適用されます（`PHAssetCreationRequest` に raw + photo の
  2 リソースとして同一アセットに保存）
- 非対応の形式はメニューに表示されません。設定画面に端末の対応状況を明示

### 写真管理

撮影直後のプレビュー / ピンチ・ダブルタップで拡大 / 撮影情報（ISO・シャッター・EV・
レンズ・WB・ルック・解像度・撮影日時）/ 共有 / 削除 / ライブラリ一覧
（撮影情報はアプリ内の `capture-log.json` にのみ保存）

## 4. 無音撮影について（重要な注記）

- iOS の標準撮影経路（`AVCapturePhotoOutput`）では、システムがシャッター音を再生します。
  **非公開 API や不正な回避手段は使用していません。**
- 代替として、公開 API の映像ストリーム（`AVCaptureVideoDataOutput`）から静止画フレームを
  保存する「サイレント撮影（フレームキャプチャ）」を実装しています。
  通常撮影と同一のカラーパイプラインを通すため色味は一致しますが、
  保存解像度は映像ストリームの解像度に依存します。
- **シャッター音が法令により必須とされる地域（日本）では、この機能は自動的に無効化**され、
  理由を UI に表示します（`CameraController.isSilentCaptureAvailable`）。
  システムの制約を尊重し、回避は行いません。

## 5. RAW / ProRAW の実装方針

- RAW ピクセルフォーマットは `availableRawPhotoPixelFormatTypes` から実行時に選択
- ProRAW のピクセルフォーマットは `'prog'`（`kCVPixelFormatTypeType_ProRAW`）として照合
  （SDK の定数名に依存しないよう `CameraController.proRAWPixelFormat` に独自定義）
- 実際に撮影に使用したピクセルフォーマットは撮影情報に記録されます

## 6. 技術的な品質

- セッション操作・デバイス制御は専用バックグラウンドキュー（UI スレッドをブロックしない）
- プレビュー処理は 30fps に制限し、長辺 1440px に縮小して処理（発熱・消費電力を抑制）
- ヒストグラム / ゼブラ / ピーキングは 160×120 の解析専用ラスタで 10Hz 実行
- カラーキューブは `NSCache` でキャッシュ（ルック変更時のみ再構築）
- 撮影デリゲートは二重完了を防止し、セッション中断・実行時エラー・バックグラウンド移行を処理
- メモリ節約のためのフレームバッファ参照保持と、レビュー画像の長辺 2048px 制限
- 撮影画像は端末内（写真ライブラリ）のみ。**外部サーバーへの送信は一切なし**

## 8. 動作確認の目安（Step 6 チェックリスト）

1. 実機でプレビューが表示され、露出・フォーカスが自動で追従する
2. AUTO で撮影 → レビュー表示 → ライブラリに保存される
3. PRO で ISO / シャッター / MF / WB を変更 → プレビューと写真の両方に反映される
4. ルック強度・画像調整を変更 → 保存写真の色がプレビューと一致する
5. RAW / ProRAW 保存 → DNG が無改変で保存され、現像済みコピーにルックがかかる
6. タイマー / 連写 / サイレント撮影（利用可能な地域）が動作する
7. ヒストグラム・ゼブラ・ピーク・水平器が個別にオン・オフできる
8. バックグラウンド移行 → 復帰でカメラが正常に再開する
